# Байт-код и VM

## Инструкции

Каждая инструкция — однобайтовый опкод, за которым идёт операнд фиксированного
размера. Операнды кодируются little-endian.

| Мнемоника | Операнд | Действие |
| --- | --- | --- |
| `const` | u16 индекс пула констант | положить константу на стек |
| `str` | u16 индекс пула строк | создать `String` на куче и положить `Ref` |
| `new` | u16 индекс имени типа | создать объект типа и положить `Ref` |
| `getf` | u16 индекс поля | снять объект, положить значение поля |
| `setf` | u16 индекс поля | снять значение и объект, записать поле, вернуть значение |
| `ldg` | u16 индекс имени глобала | положить глобальную переменную |
| `stg` | u16 индекс имени глобала | записать вершину в глобальную и вернуть её |
| `ldl` | u16 слот | положить локальную переменную |
| `stl` | u16 слот | записать вершину в локальную |
| `pop` | — | снять вершину |
| `add` / `sub` / `mul` / `div` | — | арифметика |
| `neg` / `not` | — | унарные операции |
| `equ` / `neq` | — | равенство (любые типы) |
| `lss` / `leq` / `gtr` / `geq` | — | сравнение чисел |
| `mod` | — | остаток (`std::fmod`), деление на ноль — ошибка |
| `and` / `or` / `xor` | — | побитовые операции над целой частью числа |
| `bnot` | — | побитовое НЕ |
| `shl` / `shr` | — | сдвиги; величина — целое в диапазоне `0..63` |
| `jmp` | i16 смещение | безусловный относительный переход |
| `jif` | i16 смещение | переход, если вершина ложна |
| `jmpa` | u32 адрес | безусловный абсолютный переход |
| `jifa` | u32 адрес | переход по адресу, если вершина ложна |
| `call` | u16 индекс имени функции | вызов функции/метода |
| `ret` | — | вернуть вершину как результат |

`call`, `new`, `ldg`, `stg` и `str` ссылаются на **имена** в пуле строк, а не на
индексы таблиц символов. VM разрешает имена при загрузке модулей, поэтому
порядок загрузки и импорты не влияют на корректность.

`jmp`/`jif` используют относительное смещение от адреса **после** операнда.
`jmpa`/`jifa` зарезервированы для дальних переходов (компилятор пока использует
относительные).

## Тело функции: XenonBinary

```cpp
class XenonBinary
{
    std::vector<std::uint8_t> _code;      // поток инструкций
    std::vector<Value>        _constants; // пул констант
    std::vector<std::string>  _strings;   // имена и строковые литералы
    std::vector<int>          _lines;     // номер строки исходника для каждого байта
};
```

Пул констант и строк адресуется 16-битными индексами (до 65535 записей).
Ограничение проверяется кодогенератором с понятной ошибкой.

## Модель исполнения

- Стек операндов принадлежит `Runtime` (класс `VirtualStack`).
- Каждый вызов создаёт **кадр**: указатель на `XenonBinary`, счётчик инструкций
  (`ip`) и массив локальных слотов.
- Параметры занимают слоты `0..arity-1`, далее идут локальные переменные.
- `call` снимает аргументы со стека и заполняет параметры вызываемого кадра.
- `ret` снимает кадр и передаёт результат вызывающему; для верхнего кадра
  результат попадает в `lastValue`.
- Функция/метод с `Defined = false` (объявление из `.hint`/`.extern`)
  исполняется как внешний вызов: VM ищет нативную реализацию через
  `registerNative` или определённую функцию с тем же именем в другом модуле.

## Связывание имён

```cpp
std::unordered_map<std::string, Executable> _executables; // функции и методы
std::unordered_map<std::string, const Type*> _types;      // классы/структуры/перечисления
std::unordered_map<std::string, Value>       _globals;    // глобальные переменные
```

- Методы регистрируются под именем `Type::method`.
- При совпадении имён определённая функция имеет приоритет над объявлением
  (`Defined = false`).
- `jif`/`jifa` снимают вершину стека и используют `truthy`: `false`, `0.0` и
  `null` ложны, остальные значения истинны.

## Формат файла `.module`

Бинарный, little-endian, магия `XENM`, версия **5**.

| Поле | Тип |
| --- | --- |
| магия | `'X' 'E' 'N' 'M'` (4 байта) |
| версия | u32 (= 5) |
| имя модуля | строка (u32 длина + байты) |
| импорты | u32 количество + строки |
| атрибуты модуля | список атрибутов |
| функции | u32 количество + записи |
| типы | u32 количество + записи |
| глобалы | u32 количество + записи |

Строка — `u32` длина + байты UTF-8. Атрибут — `u8` вид (`none`, `integer`,
`float`, `string`, `object`), строка ключа и значение выбранного вида.
Шаблонный параметр — флаг значения, имя типа, тип по умолчанию, тип значения,
значение по умолчанию.

Запись функции:

```
имя, сигнатура, export(u8), defined(u8), arity(u32), locals(u32),
XenonBinary, атрибуты, шаблонные параметры
```

Запись метода добавляет `access(u8)`.

Запись типа:

```
имя, kind(u8: class/struct/enum), export(u8), defined(u8),
поля (тип, имя, access(u8), export(u8), атрибуты, шаблоны),
методы (запись метода),
перечислители (u32 + строки),
родители (access(u8), имя),
атрибуты, шаблонные параметры
```

Запись глобала:

```
тип, имя, export(u8), constant(u8), значение, атрибуты, шаблоны
```

`XenonBinary` сериализуется как: код (u32 размер + байты), константы
(u32 + значения), строки (u32 + строки), номера строк (u32 + i32).

Значения (`Value`) кодируются тегом:

| Тег | Значение |
| --- | --- |
| 0 | `null` |
| 1 | `bool` |
| 2 | `double` |
| 3 | `Ref` (u32 id) |

Чтение неверных или обрезанных файлов выбрасывает `xenon::ModuleFileError`.

## Упаковка `.xenon`

Файл `.xenon` — ZIP-архив (метод STORE, без сжатия) с манифестом
`META-INF/MANIFEST.MF`:

```
Manifest-Version: 1.0
Main-Module: Example
Main-Function: main
```

`xenon run package.xenon` загружает **все** `.module` из архива и запускает
точку входа из манифеста.
