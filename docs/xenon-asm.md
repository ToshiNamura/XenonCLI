# Xenon ASM — архитектура

Xenon ASM — единое ассемблерное представление для виртуальной машины Xenon:
последовательность инструкций, которая описывает и исполняемый код, и данные.
Каждая инструкция кодируется как `[opcode: u8] [operands...]`.

> **Статус реализации.** Модель данных, ассемблер, дизассемблер и бинарный
> формат `.module` реализованы. Команды: `xenon asm`, `xenon disasm`.
> Компилятор выдаёт ту же модель, что и ассемблер; дизассемблерный текст можно
> собрать обратно и исполнить.

## 1. Обзор

Xenon ASM — единое ассемблерное представление: поток инструкций, который
описывает **и код, и данные**:

- исполняемый код функций и методов виртуальной машины;
- декларации: классы, структуры, функции, методы, перечисления, шаблоны,
  глобальные переменные.

Бинарный Xenon ASM имеет человекочитаемое текстовое представление в
ассемблерном синтаксисе; весь конвейер (компилятор → сериализация → VM →
дизассемблер) работает с этим единым форматом.

## 2. Единый поток инструкций

Xenon ASM — это **последовательность инструкций, организованная в секции**, где
каждая инструкция кодируется как:

```
[opcode: u8] [operands...]
```

Инструкции делятся на два семейства:

| Семейство | Роль | Пример |
| --- | --- | --- |
| **Директивы** | описывают структуру и данные (не исполняются, «собирают» функции и данные) | `.class`, `.field`, `.function` |
| **Инструкции** | исполняемый VM-код | `add`, `call`, `ret` |

Директивы — это те же опкоды, но из отдельного диапазона. Благодаря этому один
поток байтов может быть одновременно «описанием функций и данных» и «кодом».

Пример (текстовое представление):

```asm
.text
    .function export double add(double a, double b)
        .local double total
        ldl 0           ; a
        ldl 1           ; b
        add
        stl 2           ; total
        ldl 2
        ret
    .end
.end

.types
    .class export Point
        .field public double x
        .field public double y
        .method public double length()
            ; тело метода
        .end
    .end
.end
```

## 3. Два представления

Одна и та же сущность существует в двух видах:

1. **Текстовый Xenon ASM** (`.asm`) — ассемблерный синтаксис для человека,
   дизассемблера и ручного написания.
2. **Бинарный Xenon ASM** — компактное кодирование для `.module` и исполнения.

Между ними два преобразования:

```
.ixx ──(компилятор)──► бинарный ASM ──(VM)──► результат
                          ▲   │
        (ассемблер)       │   │ (дизассемблер)
                          │   ▼
                       текстовый ASM
```

## 4. Текстовый синтаксис

- Одна инструкция/директива на строку.
- `;` — комментарий до конца строки.
- Мнемоники инструкций — строчными буквами, 3–6 символов (`add`, `call`, `ret`).
- Директивы начинаются с `.` (`.class`, `.field`, `.end`).
- Открывающие директивы (секции, типы, функции) задают область действия; `.end`
  закрывает ближайшую открытую область.
- Переходы задаются числовым смещением (`jmp`/`jif`) или адресом
  (`jmpa`/`jifa`). Именованные метки (`loop:`) — планируемая возможность.

### Секции

Поток разбит на пять секций:

```asm
.meta                                    ; имя модуля, импорты, атрибуты модуля
    .module Name
    .import Other
    .attribute version "1.0"
.end

.types                                   ; классы, структуры, перечисления (методы с телами)
    ...
.end

.data                                    ; глобальные переменные
    ...
.end

.text                                    ; исполняемый код функций
    ...
.end

.extern                                  ; внешние объекты (объявления из .hint)
    ...
.end
```

### Модификаторы объектов

Директивы `.attribute`, `.template` и `.parent` записываются **над** объектом и
модифицируют следующую за ними декларацию:

```asm
.attribute <ключ> <значение>
.template <параметры>
.class <имя>
.end
```

- `.attribute` — атрибут; применим к `.class`, `.struct`, `.enum`, `.function`,
  `.method`, `.field`, `.local`, `.variable`, `.constant` и к модулю (в `.meta`);
  может быть несколько.
- `.template` — параметры шаблона (типовые и значенческие); применим к `.class`,
  `.struct`, `.enum`, `.function`, `.method`, `.field`, `.variable`, `.constant`;
  может быть несколько.
- `.parent` — базовый тип (наследование); только для `.class`/`.struct`; может
  быть несколько.

Каждый объект (процедура, тип, поле, метод, глобальная переменная) хранит массив
атрибутов; шаблон и родители — отдельные списки.

### Атрибуты

Атрибут может быть одиночным (только ключ) или иметь значение. Значения бывают
четырёх видов:

```asm
.attribute <ключ>                     ; одиночный (без значения)
.attribute <ключ> 1234                ; целое число
.attribute <ключ> 12.34               ; вещественное число
.attribute <ключ> "String"            ; строка
.attribute <ключ> .class <имя>        ; ссылка на объект
```

Ссылка на объект записывается как директива, определяющая объект, за которой
следует имя объекта; вместо `.class` может стоять любая декларация объекта —
`.struct`, `.enum`, `.function`, `.method`, `.variable`:

```asm
.attribute entry .function main
.attribute var   .variable counter
```

Атрибуты могут находиться и в секции `.meta` — тогда это атрибуты модуля.

### Ключевые слова и доступ

- `export` — помечает объявление видимым снаружи модуля; применим к `.function`,
  `.method`, `.field`, `.class`, `.struct`, `.enum`, `.variable`, `.constant`.
- Классификаторы доступа `private`, `public`, `protected` — у `.field`, `.method`
  и наследования (`.parent`).
- `class` и `struct` функционально одинаковы (поля, методы, наследование);
  различие — только доступ по умолчанию:
  - `class` — `private`;
  - `struct` — `public`.

```asm
.attribute version "1.0"
.template T
.parent public Base
.class export Derived
    .field private int id
    .field public  double value
    .method public double get()
.end
```

### Наследование

Базовые типы перечисляются директивами `.parent` над `.class`/`.struct`:

```asm
.parent public Base
.parent private Mixin
.class Derived
.end
```

### Шаблоны

Шаблон — модификатор, который определяет как шаблонный тип, так и шаблонное
значение. Форма одного параметра:

```
<templateTypeName[ = defaultTemplateType]>      ; шаблонный тип
<typeName templateValueName[ = defaultValue]>   ; шаблонное значение
```

```asm
.template <T>            ; тип без умолчания
.template <T = double>   ; тип с умолчанием
.template <int N>        ; значение с типом
.template <int N = 4>    ; значение с типом и умолчанием
.class Box
.end
```

### Форма директив

```asm
.module <имя>                                       ; в .meta
.import <имя>                                       ; в .meta

.function [export] <тип> <имя>(<параметры>)         ; в .text, функция
.method [export] [access] <тип> <имя>(<параметры>)  ; в .types, метод (с телом)
.class  [export] <имя>                              ; в .types
.struct [export] <имя>                              ; в .types
.enum   [export] <имя>                              ; в .types
.parent <access> <тип>                              ; над .class/.struct

.field [export] [access] <тип> <имя>                ; в .types
.item <имя>                                          ; в .enum
.local <тип> <имя>                                  ; в .function/.method
.locals <количество>                                ; точное число слотов (дизассемблер)
.variable [export] <тип> <имя> [<значение>]         ; в .data
.constant [export] <тип> <имя> <значение>           ; в .data, константа

.attribute <ключ> [<значение>]                     ; модификатор объекта
.attribute <ключ> <директива> <имя>                ; атрибут-ссылка на объект
.template <параметры>                               ; модификатор объекта
.end                                                ; закрыть область
```

Параметры функции кодируются её подписью (строка в пуле строк), поэтому
отдельная директива `.param` не нужна. Перечислители остаются директивами
`.item`: список перечислителей — это данные перечисления `.enum`, а отдельная
строка позволяет вешать атрибут на каждый перечислитель.

## 5. Директивы

Директивы строят **функции, методы и данные** из потока. Каждая директива
несёт операнды в виде индексов в пул строк/констант и флагов.

| Директива | Секция | Что порождает | Операнды |
| --- | --- | --- | --- |
| `.meta` / `.types` / `.data` / `.text` / `.extern` | — | открыть секцию | — |
| `.module` | `.meta` | имя модуля | строка |
| `.import` | `.meta` | зависимость | строка |
| `.class` / `.struct` / `.enum` | `.types` | тип (данные) | `export` (флаг), имя (строка) |
| `.parent` | `.types` | базовый тип | доступ (u8), имя типа (строка) |
| `.field` | `.types` | поле типа | `export`+доступ (флаги), тип, имя |
| `.method` | `.types` | метод (с телом) | `export`+доступ (флаги), тип, имя, подпись, арность, локалы |
| `.item` | `.types` (в `.enum`) | перечислитель | имя |
| `.variable` | `.data` | глобальная переменная (данные) | `export` (флаг), тип, имя, начальное значение |
| `.constant` | `.data` | глобальная константа (данные) | `export` (флаг), тип, имя, значение (обязательно) |
| `.function` | `.text` | функция | `export` (флаг), тип, имя, подпись, арность, локалы |
| `.local` | `.text` | локальный слот | тип, имя |
| `.locals` | `.text` | точное число локальных слотов | количество (u16) |
| `.attribute` | любой объект, `.meta` | атрибут | ключ, значение (опционально; целое/вещественное/строка/ссылка) |
| `.template` | любой объект | параметры шаблона | список параметров |
| `.end` | везде | закрыть секцию/область | — |

Код внутри `.function`/`.method` — последовательность инструкций из раздела 6.

## 6. Инструкции

Мнемоники короткие (3–6 букв), строчными. Направление стека то же: операнды
снимаются со стека, результат кладётся обратно. Индексы в пулы — `u16`.

| Мнемоника | Операнд | Действие |
| --- | --- | --- |
| `const` | литерал (`1.5`, `true`, `null`) | добавить константу в пул и положить её |
| `str` | строка `"..."` или u16 индекс | создать `String`, положить `Ref` |
| `new` | имя типа или u16 индекс | создать объект, положить `Ref` |
| `getf` | u16 индекс поля | снять объект, положить поле |
| `setf` | u16 индекс поля | снять значение и объект, записать поле |
| `ldg` | имя глобала или u16 индекс | положить глобальную переменную |
| `stg` | имя глобала или u16 индекс | записать вершину в глобальную |
| `ldl` | u16 слот | положить локальную переменную |
| `stl` | u16 слот | записать вершину в локальную |
| `pop` | — | снять вершину |
| `add` | — | `a + b` |
| `sub` | — | `a - b` |
| `mul` | — | `a * b` |
| `div` | — | `a / b` |
| `neg` | — | `-a` |
| `not` | — | `!a` |
| `equ` | — | `a == b` |
| `neq` | — | `a != b` |
| `lss` | — | `a < b` |
| `leq` | — | `a <= b` |
| `gtr` | — | `a > b` |
| `geq` | — | `a >= b` |
| `mod` | — | `a % b` (`std::fmod`) |
| `and` | — | `a & b` (побитовое И над целыми) |
| `or` | — | `a \| b` |
| `xor` | — | `a ^ b` |
| `bnot` | — | `~a` |
| `shl` | — | `a << b` (сдвиг на `0..63`) |
| `shr` | — | `a >> b` (арифметический) |
| `jmp` | i16 смещение | относительный безусловный переход |
| `jmpa` | u32 адрес | адресный безусловный переход |
| `jif` | i16 смещение | относительный переход, если вершина ложна |
| `jifa` | u32 адрес | адресный переход, если вершина ложна |
| `call` | имя функции или u16 индекс | вызов функции/метода |
| `ret` | — | вернуть вершину как результат |

В текстовом ASM операнды-имена можно писать строкой в кавычках
(`call "Type::method"`, `new "Point"`), а `const` принимает литерал. В бинарном
виде это всегда `u16`-индекс соответствующего пула.

## 7. Бинарное кодирование

Поток — плоский массив байтов (`XenonBinary::code()`), little-endian:

- Инструкции — опкоды диапазона `0x00..0x7F`.
- Директивы существуют только в **текстовом** ASM; в `.module` они разворачиваются
  в структуры `xenon::Module` (см. [bytecode.md](bytecode.md)).
- Индексы в пул констант/строк, слоты и индексы полей — `u16`.
- Переходы: относительные — `i16` смещение; адресные — `u32` адрес; размеры
  фиксированы и не зависят от разрядности системы.
- Имена функций/методов/типов/глобалов — строки в пуле строк тела.
- Значение атрибута — тег типа (u8): отсутствует / целое (i64) / вещественное
  (f64) / строка / ссылка на объект.
- Пул констант и пул строк — боковые таблицы тела `XenonBinary`.
- Номера строк исходника сохраняются побайтово (используются для диагностики).

Пример бинарной кодировки `.function` (директива `0x80`):

```
0x80                     ; opcode .function
флаги (u8): export       ; бит 0
индекс типа (u16)        ; в пул строк
индекс имени (u16)       ; в пул строк
индекс подписи (u16)     ; в пул строк
арность (u16)
число локалов (u16)
```

Пример инструкции `add`:

```
0x09                     ; add, без операндов
```

Пример перехода `jmp`:

```
0x1A 0xFC 0xFF           ; jmp -4 (i16, little-endian)
```

> Актуальная таблица опкодов — в `include/xenon/asm/opcode.hpp`.

Бинарный формат списка шаблонных параметров (директива `.template`):

```
количество параметров (u16)
для каждого параметра:
    tag (u8)                        ; 0 — шаблонный тип, 1 — шаблонное значение
    если tag == 0 (шаблонный тип):
        имя типа (u16)              ; индекс в пул строк
        тип по умолчанию (u16)      ; индекс в пул строк; 0xFFFF — умолчания нет
    если tag == 1 (шаблонное значение):
        тип значения (u16)          ; индекс в пул строк
        имя значения (u16)          ; индекс в пул строк
        значение по умолчанию (u16) ; индекс в пул строк; 0xFFFF — умолчания нет
```

## 8. Модель данных

`Function` — функция верхнего уровня, `Method` — метод внутри типа. Обе единицы
независимы и содержат собственное исполняемое тело, `export`/доступ, атрибуты и
шаблонные параметры. Классы, структуры, перечисления и глобальные переменные —
данные.

```cpp
enum class Access : std::uint8_t
{
	Private,
	Protected,
	Public,
};

enum class TypeKind : std::uint8_t
{
	Class,
	Struct,
	Enum,
};

enum class AttributeKind : std::uint8_t
{
	None,     ///< одиночный атрибут (только ключ)
	Integer,  ///< целое число
	Float,    ///< вещественное число
	String,   ///< строка
	Object,   ///< ссылка на объект
};

/// Базовый атрибут: только ключ и тип значения (само значение — в наследниках).
struct Attribute
{
	std::string   Key;
	AttributeKind Kind = AttributeKind::None;
	virtual ~Attribute() = default;
};

using AttributeList = std::vector<std::shared_ptr<Attribute>>;

struct AttributeInteger final : Attribute
{
	AttributeInteger() { Kind = AttributeKind::Integer; }
	std::int64_t Value = 0;
};

struct AttributeFloat final : Attribute
{
	AttributeFloat() { Kind = AttributeKind::Float; }
	double Value = 0.0;
};

struct AttributeString final : Attribute
{
	AttributeString() { Kind = AttributeKind::String; }
	std::string Value;
};

struct AttributeObject final : Attribute
{
	AttributeObject() { Kind = AttributeKind::Object; }
	std::string Object;   ///< имя объекта, на который ссылается атрибут
};

// Проверка типа
//   if (attr.get().Kind == AttributeKind::Integer)
// Приведение типа выполняется по `Kind` через `dynamic_cast`:
//   const auto* integer = dynamic_cast<const AttributeInteger*>(attr.get())

struct Parent
{
	Access      AccessModifier;
	std::string TypeName;
};

struct TemplateParam
{
	std::string TypeName;     // имя шаблонного типа (пусто для значения)
	std::string DefaultType;  // = default для типа
	std::string ValueType;    // тип шаблонного значения
	std::string DefaultValue; // = default для значения
	bool        IsValue = false;
};

/// Функция: функция верхнего уровня с исполняемым телом.
struct Function
{
	std::string                Name;
	std::string                Signature;
	bool                       Exported = false;
	std::size_t                Arity = 0;
	std::size_t                Locals = 0;
	bool                       Defined = true;   // false — объявление без тела (.extern/.hint)
	XenonBinary                Body;             // поток ASM
	AttributeList              Attributes;
	std::vector<TemplateParam> TemplateParams;
};

/// Данные: поле класса/структуры.
struct Field
{
	std::string                Type;
	std::string                Name;
	Access                     AccessModifier = Access::Private; // у struct по умолчанию public
	bool                       Exported = false;
	AttributeList              Attributes;
	std::vector<TemplateParam> TemplateParams;
};

/// Метод — независимая единица: сигнатура + доступ + исполняемое тело.
struct Method
{
	std::string                Name;
	std::string                Signature;
	Access                     AccessModifier = Access::Private; // у struct по умолчанию public
	bool                       Exported = false;
	std::size_t                Arity = 0;
	std::size_t                Locals = 0;
	bool                       Defined = true;   // false — объявление без тела (.extern/.hint)
	XenonBinary                Body;             // поток ASM
	AttributeList              Attributes;
	std::vector<TemplateParam> TemplateParams;
};

/// Данные: класс, структура или перечисление.
struct Type
{
	std::string                Name;
	TypeKind                   Kind = TypeKind::Class;
	bool                       Exported = false;
	std::vector<Field>         Fields;
	std::vector<Method>        Methods;           // методы (с телами)
	std::vector<std::string>   Enumerators;       // перечисления
	std::vector<Parent>        Parents;
	AttributeList              Attributes;
	std::vector<TemplateParam> TemplateParams;
};

/// Данные: глобальная переменная.
struct Global
{
	std::string                Type;
	std::string                Name;
	bool                       Exported = false;
	bool                       Constant = false;
	Value                      InitialValue = Null{};
	AttributeList              Attributes;
	std::vector<TemplateParam> TemplateParams;
};

/// Модуль — имя, импорты, функции и данные.
struct Module
{
	std::string               Name;
	std::vector<std::string>  Imports;
	std::vector<Function>     Functions;     // функции
	std::vector<Type>         Types;         // данные: типы (методы — внутри)
	std::vector<Global>       Globals;       // данные: глобальные переменные
};
```

- **Ассемблер** читает бинарный ASM и строит `Module` (функции + типы + глобалы).
- **Дизассемблер** — обратно: `Module` → бинарный/текстовый ASM.
- VM исполняет тела `Function` и `Method`; типы и глобалы — данные для связывания
  и доступа к полям/методам.
- Доступ по умолчанию: `class` — `private`, `struct` — `public`; ассемблер/
  компилятор всегда записывают модификатор явно.
- Объекты секции `.extern` — внешние объявления (из `.hint`): функции и методы
  с `Defined = false` (исполняются как внешние вызовы), типы и глобалы,
  предоставляемые хостом.

Это даёт инкрементную миграцию: ASM появляется как формат сериализации и
текстовый вид, а модель данных остаётся плоской и не раздувается.

## 9. Инструменты

- **Ассемблер** (`Assembler`): текст `.asm` → бинарный ASM → `Module`.
- **Дизассемблер** (`Disassembler`): бинарный ASM → текст `.asm` (сейчас он
  печатает только поток опкодов — его нужно расширить до директив и меток).
- **Компилятор**: `codegen` начинает генерировать не `XenonBinary`, а
  инструкции ASM (директивы + мнемоники).

## 10. Принятые решения

- Мнемоники инструкций — короткие, 3–6 букв.
- Индексы в пулы — `u16`.
- Переходы — две пары: относительный (`jmp`, `jif`) и адресный (`jmpa`, `jifa`);
  размеры фиксированы (`i16` / `u32`) и не зависят от разрядности системы.
- Подпись функции кодируется явно (строка в пуле строк).
- Секции `.meta`/`.types`/`.data`/`.text`/`.extern` — используются.
- Диапазоны опкодов: инструкции `0x00..0x7F`, директивы `0x80..0xFF`.
- Имена директив — длинные (`.attribute`, `.constant`); перечислитель — `.item`.
- Глобальные константы — отдельная директива `.constant`.
- `Function` и `Method` — независимые единицы (с телом); `Type` и `Global` —
  данные; ASM — формат сериализации и текстовый вид.
- Таблица строк исходника (debug) — по умолчанию не сохраняется; в будущем —
  флаг компилятора.
